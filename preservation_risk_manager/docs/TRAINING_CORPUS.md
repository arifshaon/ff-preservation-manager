# Training corpus (Corpus A)

This document covers **Corpus A**, the supervised fine-tuning set for the risk-answer
interpreter. It is built by `build-training-corpus` from evidence the registry already
holds — no new data acquisition is required.

Corpus B (the retrieval/literature index for criteria no registry covers) is a separate
system and is deliberately **not** built yet. The gap list from `evidence_gaps.py` is what
tells you which documents are worth acquiring, so Corpus B is cheaper and better targeted
after Corpus A exists.

## What the model is being taught

One narrow task, matching what `review_answers_with_ai` asks at inference time:

> Given one framework question and a bounded set of raw source evidence, choose exactly one
> controlled answer, cite the supplied evidence that supports it, and abstain when the
> evidence does not establish an answer.

The corpus does **not** teach scoring, banding, posture, or action policy. Those stay
deterministic and authoritative.

## The example unit

One example per `(format, question)` pair, written as JSONL:

```json
{
  "messages": [
    {"role": "system", "content": "<RISK_INTERPRETER_SYSTEM_PROMPT>"},
    {"role": "user", "content": "<question_evidence + _question_prompt output>"},
    {"role": "assistant", "content": "{\"question_id\":\"q_disclosure\",\"answer_id\":\"public_specification\",\"confidence\":0.8,\"rationale\":\"...\",\"evidence_refs\":[\"E001\"],\"uncertainty\":\"\"}"}
  ],
  "meta": {
    "canonical_id": "puid-fmt-18",
    "question_id": "q_disclosure",
    "criterion": ["sustainability.disclosure"],
    "label_source": "nara_rubric",
    "tier": "A",
    "framework_version": "0.1.0-draft",
    "corpus_version": "2026-09"
  }
}
```

`meta` never reaches the model. It exists for splitting, filtering, and auditing, and a test
asserts none of its keys appear in the message contents.

### The assistant target uses the real response schema

The target is the six-field object that `_response_schema()` declares and
`_validate_ai_answer()` enforces — `question_id`, `answer_id`, `confidence`, `rationale`,
`evidence_refs`, `uncertainty` — not a simplified `{answer_id, citations, reasoning}` shape.
A model trained on a different shape produces output the validator rejects, so the corpus
targets the schema the pipeline actually checks.

Citations are therefore `evidence_refs` (`E001`, `E002`, …) pointing into the evidence list
supplied in that same prompt. The `source_id`/`field`/`value` form is retained in
`meta.citations` for auditing.

### Prompts are generated by the inference code

`training_corpus.py` calls `question_evidence()` and `_question_prompt()` directly rather
than reimplementing them. A corpus whose prompts differ in shape from production prompts
trains the model for a task it will never be asked to perform.
`test_corpus_prompt_matches_the_inference_prompt_exactly` captures the prompt that
`review_answers_with_ai` sends and asserts the corpus prompt is identical, so a change to
either side fails the build rather than silently degrading the corpus.

### Evidence is the review-all sanitized view

Inputs are built through `raw_review_evidence_pack()` — the same view independent review
uses. This matters for leakage: an unsanitized criterion claim carries
`"value": "public_specification"`, which *is* the label. The sanitized view exposes only the
raw source payload and provenance (`source_field`, `source_value`, `link_basis`, …), so the
model must read "Does the format have a published open specification? → 2" rather than copy
a normalized answer.

## Leakage and the three tiers

Labels come from NARA. NARA evidence is also in the registry. Showing a model NARA's answer
and asking it to predict NARA's answer measures transcription, not interpretation.

| Tier | Input evidence | Purpose | Used for |
| --- | --- | --- | --- |
| **A** | No NARA claims at all | Clean supervision | **Train + evaluate** |
| **B** | NARA's answer to *this* question removed, its other answers retained | Format/citation discipline on more data | Train only |
| **C** | None, or evidence that does not address the criterion | Abstention | Train only |

**Train on A + B + C. Evaluate only on held-out Tier A.** Anything else measures
memorisation. Tier B and Tier C examples belonging to a test or validation format are
*discarded*, not moved to train — moving them would place the same format on both sides of
the split, which is the leak the split exists to prevent.

Tier A additionally requires evidence that survives the filter *and* addresses the question.
Without it the example would pair a confident answer with a prompt that cannot justify it —
training the model to answer from nothing, which is precisely the failure Tier C exists to
prevent.

### Tier B only counts when it differs from Tier A

`question_evidence()` selects evidence matching *this question's* declared
`evidence_fields`. NARA answers to other criteria are retained by Tier B but never enter the
prompt, so whenever a format's only relevant NARA claim is the one being withheld, Tier B
produces an input byte-identical to Tier A. Those duplicates are dropped and counted as
`tier_B_duplicate_of_tier_a`; keeping them would double-weight those formats for no extra
signal.

On the current registry **every** Tier B example was a duplicate. Tier B becomes productive
only when a question draws on several criteria, or when the evidence selector is widened.

### Confidence is a prior, not a calibration

The corpus has no ground truth for how certain a reading should be. `confidence` is derived
deterministically from corroboration across independent sources and claim `directness`, so
the model learns to vary confidence with evidence strength instead of emitting a constant.
Recalibrate it against held-out agreement after training; do not read it as measured
accuracy.

## Abstention is mandatory

A model trained only on answerable questions stops abstaining, and an accuracy metric
computed over well-evidenced formats will not reveal it. Tier C builds two variants:

- `no_evidence` — nothing supplied.
- `inconclusive` — evidence supplied, but none of it addresses the criterion.

The target share is `--abstention-share` (default 0.12) with `--abstention-tolerance`
(default 0.03) as a build-failing band. Tier C is sized against the answerable examples that
survive splitting, and generated only for training formats, so the realised share matches the
target exactly rather than drifting when held-out rows are dropped.

## Splitting

By format, never by row. Two questions about PDF share that format's evidence and identity,
so a row-level split would put correlated examples on both sides of the boundary.

```
--split-seed 20260901   deterministic; the same seed always yields the same partition
--test-share 0.15
--val-share 0.10
```

## Quality gates

The build **fails** (exit code 2) when any gate is violated. The corpus is still written so a
failed build can be inspected rather than only described.

| Gate | Why |
| --- | --- |
| `tier_a_contains_no_nara_evidence` | Tier A is the evaluation set; NARA in the input makes it a transcription test |
| `citations_resolve_to_supplied_evidence` | An unresolvable ref teaches hallucinated citation |
| `no_format_in_two_splits` | Format-level leakage |
| `every_bound_question_has_minimum_test_examples` | Per-question agreement needs a denominator |
| `answer_distribution_not_degenerate` | A >90% majority class means a constant predictor scores as well as the model |
| `abstention_share_within_band` | Too few and it over-answers; too many and it over-abstains |

Two distinctions the gates draw deliberately:

- The distribution gate is computed over **answerable examples only**. Tier C is 100%
  abstention by construction, so including it would flag every question as degenerate.
- A question carrying only Tier C examples is reported as
  `questions_without_answerable_examples`, not as a thin sample. That is a *coverage* gap —
  the registry holds no label for it — and belongs to `evidence_gaps.py`, not to resampling.

## Usage

```bash
python -m preservation_risk_manager build-training-corpus \
  --storage-config config/storage.mongodb.json \
  --framework config/frameworks/qnl_preservation_risk_questions.v1.json \
  --tiers A,B,C \
  --abstention-share 0.12 \
  --split-seed 20260901 \
  --corpus-version 2026-09 \
  --out corpus/
```

`--registry-json` works in place of `--storage-config` for file exports. `--max-formats`
caps the scan for smoke runs.

Outputs:

```
corpus/2026-09/
  train.jsonl   val.jsonl   test.jsonl
  manifest.json         counts by tier/question/criterion/answer, settings, seed, source IDs
  leakage_report.json   every gate result with violating examples
```

## Measured volume

Built against the full registry export (3,365 current formats, 8,887 criterion claims) with
the three-question sustainability framework:

| Quantity | Measured |
| --- | --- |
| Formats with a usable NARA label | 370 |
| Tier A examples | 183 |
| Tier B examples | 0 (all duplicated Tier A) |
| Answerable questions | 1 of 3 |

This is well below the ~2,700 Tier A estimate, for two structural reasons worth knowing
before planning a training run.

**NARA covers four criteria.** `sustainability.disclosure`, `technical.identifiability`,
`technical.renderer_availability`, and `sustainability.tpm_encryption` — 758 formats each.
A framework question can only be labelled where NARA and the question's `evidence_fields`
overlap. For the sustainability framework that is `disclosure` alone; `adoption` and
`external_dependencies` have no NARA claims and yield only Tier C.

**The negative class is being discarded by a mapping gap.** NARA disclosure values are
`public_specification` (373), `undocumented` (336), and `unknown` (49). The shared
`DERIVATION_VALUE_MAP["sustainability.disclosure"]` has no entry for `undocumented`, so those
336 claims derive no answer and never become labels. The surviving labels are then ~100%
`public_specification`, which fails the degeneracy gate — correctly, since a constant
predictor would score 1.0.

Adding `undocumented` to the question's own `evidence_value_map` (the framework-local
extension point, checked before the shared map) raises Tier A from 183 to 245 and moves the
distribution to 183/62, which passes. Fixing it in the shared map instead would change
deterministic risk scores for every affected format, so that decision belongs to framework
review rather than to corpus construction.

## Sequencing

| # | Step | Output |
| --- | --- | --- |
| 1 | Widen labelled criteria (LOC corroboration, `undocumented` mapping) | Larger, non-degenerate Tier A |
| 2 | `build-training-corpus` with gates green | Versioned corpus + manifest |
| 3 | `analyze-format-ai --mode review-all` on the test split, no fine-tuning | Baseline per-question agreement |
| 4 | QLoRA on 7B–14B **only if the baseline falls short** | Adapter, versioned in `model_name` |
| 5 | Re-measure on held-out Tier A | Auto-trust thresholds per question |
| 6 | Corpus B for the remaining gaps | Claims for uncovered criteria |

Steps 1–3 need no GPU and produce the number that decides whether step 4 is worth doing. If a
14B model already agrees at 0.92 per question, fine-tuning may not be worth the spend — and
that is only knowable by measuring first.
