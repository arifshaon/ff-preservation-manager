# Installation

This guide starts from a fresh clone and lets you install only the parts you need.

## Requirements

- Python 3.10 or later
- Git
- network access for online source acquisition
- MongoDB only if you want the persistent MongoDB registry
- an AI-provider account/key only if you want AI-assisted analysis

Windows PowerShell examples are used below. Equivalent commands work on Linux/macOS.

## 1. Clone and create one virtual environment

```powershell
git clone https://github.com/arifshaon/ff-preservation-manager.git
cd ff-preservation-manager

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Using one virtual environment for both modules is recommended because the Risk Manager can reuse the Registry Builder's storage adapters for MongoDB access.

## Installation option A — Registry Builder only, no MongoDB

Use this when you want to acquire/normalize data and inspect exports without running a persistent database.

```powershell
cd qnl_format_registry_builder
python -m pip install -e ".[dev]"
pytest -q
```

The builder supports memory/file/export workflows without MongoDB.

Example registry-construction run:

```powershell
python -m registry_builder run `
  --config config\sources.example.json `
  --workdir work `
  --out output
```

For a cross-package export that includes mapped criterion claims, use the criterion-mapping quickstart configuration documented in the module reference.

## Installation option B — Persistent local registry with MongoDB

Use this for the normal maintained local registry.

### B1. Install/start MongoDB

Install MongoDB Community Server for your operating system and ensure it is running on the configured URI. The checked-in QNL configuration uses:

```text
mongodb://localhost:27017
Database: qnl_format_registry
```

A simple connectivity check with `mongosh` is:

```powershell
mongosh "mongodb://localhost:27017" --eval "db.adminCommand({ ping: 1 })"
```

### B2. Install the Registry Builder with MongoDB support

```powershell
cd qnl_format_registry_builder
python -m pip install -e ".[dev,mongo]"
pytest -q
```

### B3. Verify the reviewed source configuration

```powershell
Get-Content config\sources.qnl.json
```

Do not put credentials into committed source configurations.

The production-style source configuration uses incremental updates so a selected-source refresh does not remove evidence from other sources.

## Installation option C — Preservation Risk Manager

If the Registry Builder was installed in the same environment, move to the Risk Manager and install it:

```powershell
cd ..\preservation_risk_manager
python -m pip install -e ".[dev]"
pytest -q
```

This is enough for deterministic/governed risk analysis with no AI and no web UI.

Example:

```powershell
python -m preservation_risk_manager ask `
  "What is the preservation risk of fmt/276?" `
  --framework examples\qnl_preservation_risk_questions.framework.draft.json `
  --storage-config ..\qnl_format_registry_builder\config\sources.qnl.json `
  --ai-mode off
```

## Installation option D — Risk Manager with AI

Install the optional OpenAI SDK dependency:

```powershell
python -m pip install -e ".[dev,ai]"
```

Create a local, uncommitted AI configuration:

```text
preservation_risk_manager\config\ai.local.json
```

Provider examples are documented in [`AI_PROVIDERS.md`](AI_PROVIDERS.md).

Validate configuration without printing the API key:

```powershell
python -m preservation_risk_manager.ai.cli info --config config\ai.local.json
```

Then run:

```powershell
python -m preservation_risk_manager ask `
  "What is the preservation risk of fmt/276?" `
  --framework examples\qnl_preservation_risk_questions.framework.draft.json `
  --storage-config ..\qnl_format_registry_builder\config\sources.qnl.json `
  --ai-config config\ai.local.json `
  --ai-mode synthesize
```

## Installation option E — Web UI, REST API and Swagger

Install the web dependencies. If you also want AI, install both extras together:

```powershell
python -m pip install -e ".[dev,ai,web]"
```

Without AI:

```powershell
python -m pip install -e ".[dev,web]"
```

Run the web application:

```powershell
python -m preservation_risk_manager.web_cli `
  --framework examples\qnl_preservation_risk_questions.framework.draft.json `
  --storage-config ..\qnl_format_registry_builder\config\sources.qnl.json `
  --host 127.0.0.1 `
  --port 8080
```

If AI should be available to web jobs, add:

```powershell
--ai-config config\ai.local.json
```

Open:

```text
Curator UI:  http://127.0.0.1:8080/
Swagger UI:  http://127.0.0.1:8080/api/docs
Health:      http://127.0.0.1:8080/api/health
```

Swagger is generated by FastAPI from the same API used by the web application; it is not a separate server/module.

See [`API_AND_SWAGGER.md`](API_AND_SWAGGER.md).

## Recommended full developer/operator installation

From one virtual environment:

```powershell
cd qnl_format_registry_builder
python -m pip install -e ".[dev,mongo]"

cd ..\preservation_risk_manager
python -m pip install -e ".[dev,ai,web]"
```

Run tests:

```powershell
cd ..\qnl_format_registry_builder
pytest -q

cd ..\preservation_risk_manager
pytest -q
```

## What is installed where

| Component | Python package / command |
| --- | --- |
| Registry Builder | `registry_builder`; `python -m registry_builder`; `qnl-registry-refresh` |
| Risk Manager | `preservation_risk_manager`; `python -m preservation_risk_manager`; `preservation-risk-manager` |
| Batch reporting | `python -m preservation_risk_manager batch-report`; `preservation-risk-batch` |
| Web UI/API | `python -m preservation_risk_manager.web_cli`; `preservation-risk-web` |
| Swagger | served by web app at `/api/docs` |
