# Prompt: propose criterion mapping config

You are helping draft a registry-builder criterion mapping file. Return **only JSON** matching the schema below. Do not include prose, markdown fences, or comments.

## Design rule

Criterion claims are observations. Hazard bands are conclusions. Actions are decisions. Readiness is capability. Framework binding is judgement.

The registry builder may store neutral observations, but must not encode an institution's scoring or convert a composite source risk rating into a framework criterion.

## Inputs you will receive

1. `criteria`: the neutral criterion vocabulary and allowed values.
2. `source_profile`: field inventory for one source, including distinct native values and counts.
3. `existing_accepted_examples`: accepted mapping examples from other sources.
4. `negative_rules`: fields and patterns that must not map to criterion claims.

## Output JSON schema

Use `source_id`, `source_type`, or both. At least one must be a real value. If `source_type` is unknown, omit that property rather than inventing a placeholder.

{
  "source_id": "<source id if known>",
  "mapping_version": "YYYY-MM-DD-draft",
  "criteria_version": "v1",
  "native_vocabulary": "<native vocabulary name>",
  "mapping_mode": "ai_draft",
  "drafted_by": "llm",
  "model_id": "<model name if known>",
  "prompt_version": "propose_mapping/v1.0",
  "review_status": "pending",
  "claim_review_status": "unreviewed",
  "decided_by": null,
  "decided_at": null,
  "excluded_from_criteria": [
    {"field": "<native field>", "reason": "<why excluded>"}
  ],
  "maps": [
    {
      "id": "<source>.<criterion>.<field>.v1",
      "criterion": "<criterion id from vocabulary>",
      "from_field": "<field path from source_profile>",
      "directness": "explicit | derived | inferred",
      "covers": "full | partial",
      "covers_note": "<required when covers is partial>",
      "source_independence": "independent | source_derived | institution_scoped",
      "mapping_status": "draft | needs_review | no_criterion",
      "values": {
        "<native value from source_profile>": "<criterion value from enum>"
      },
      "when_present": "<criterion value, only for inferred presence mappings>",
      "rationale": "<why this field maps to this criterion>"
    }
  ],
  "no_criterion": [
    {
      "field": "<native field>",
      "reason": "<why no current criterion fits>",
      "suggests_vocabulary_extension": "<optional criterion id>"
    }
  ],
  "needs_review": [
    {
      "field": "<native field>",
      "reason": "<why a human must decide>"
    }
  ]
}

## Mandatory validator-compatible draft rules

- Root `claim_review_status` is required and must be `unreviewed` for an AI draft.
- Do not set an accepted/approved mapping status in an AI draft.
- Do not set `decided_by`; AI drafts are never approved.
- Use a real `source_id`, `source_type`, or both. Do not return literal placeholder strings as identifiers.
- Every target value in `values`, `text_rules`, or `when_present` must exist in the uploaded criterion vocabulary.

## Mandatory negative rules

- Do not map a composite risk level, risk score, numeric risk rating, hazard band, or overall assessment to a criterion. Put it in `excluded_from_criteria` with reason: `composite conclusion; hazard estimator only`.
- Do not map preservation action, proposed plan, or preferred tools to a sustainability or technical criterion. These are action/readiness signals, not hazard criteria.
- Do not map a URL merely being present to `public_specification`. Presence can at most infer `partial_specification`, with `directness: inferred` and a confidence/rationale note.
- Do not wildcard NARA rubric questions. Each NARA question must be mapped individually or left as `needs_review`.
- Do not invent criteria or criterion values. If no criterion fits, put the field in `no_criterion`.
- Do not force every field into a mapping. Declining to map a field is a valid outcome.

## Directness rules

- `explicit`: the source directly states the same observation as the criterion.
- `derived`: the source field must be transformed or interpreted but remains non-composite.
- `inferred`: the source does not state the criterion directly; mapping is weak evidence.

## Source independence rules

- `independent`: source states its own observation.
- `source_derived`: source value is copied or derived from another authority.
- `institution_scoped`: local/institutional observation, usable only in institution-scoped analysis.

## Important

Return the safest draft, not the most complete draft. Fields with ambiguous semantics should be `needs_review` or `no_criterion`, not guessed.
