# Prompt: transcribe an unstructured preservation source

Use this prompt with an AI agent after uploading the exact source PDF/HTML/text and the transcription schema:

```text
config/schemas/unstructured_source_transcription.v1.schema.json
```

You are drafting a structured transcription of an unstructured preservation source for the QNL File Format Registry Builder.

Your job is **source transcription only**. Preserve what the supplied publication says in source-native language and structure it into the supplied JSON schema.

## Inputs

I will provide:
1. the exact source PDF, HTML export, text, or images;
2. `unstructured_source_transcription.v1.schema.json`;
3. source identity/edition metadata if known;
4. optionally a previously reviewed transcription example.

## Non-negotiable rules

- Use only the supplied source for factual transcription unless I explicitly authorize outside research.
- Do not invent file formats, extensions, MIME types, identifiers, dates, categories, trends, rationales, or source locators.
- Do not use your general knowledge to fill missing fields.
- Preserve source-native categories/wording in `native_fields` rather than translating them into QNL risk criteria.
- Do not calculate a QNL risk score or Low/Moderate/High band.
- Do not convert preservation actions into sustainability criteria.
- Do not infer PUIDs, LOC IDs, MIME types, or extensions unless the source explicitly supplies them.
- Every record must retain a source locator: page, section, heading, anchor, or source URL.
- If a value is unclear, omit/null it and add an explanation to `needs_review` or `transcription_notes`.
- Keep source excerpts short and only where useful for verification.
- Set `review_status` to `draft`.
- Set `reviewed_by` and `reviewed_at` to null.
- You are not the human reviewer.
- If AI is used, set `transcription_method` to `ai_assisted`, `transcribed_by` to `llm`, and include `model_id` if known.
- Return JSON only. No markdown fence. No commentary outside JSON.

## Record design

For each source entry, produce a stable `source_record_id` based only on source-supported identity, edition, and a deterministic slug/number. Do not fabricate an authority identifier.

Use normal identity fields when the source states them:

```text
name
category
description
extensions
mime_types
identifiers
urls
```

Put source-specific observations under:

```text
native_fields
```

Examples of source-native observations might include:

```text
endangerment_category
trend
software_support_statement
adoption_statement
dependency_statement
rationale
recommended_action
```

These names are examples only. Prefer field names that reflect the supplied publication and remain stable across records.

A source-level conclusion such as an endangerment category should remain source-native. Do not reinterpret it as a primitive neutral criterion during transcription.

## Provenance

For each record preserve as many of these as the source supports:

```text
source_page
source_section
source_heading
source_anchor
source_url
source_excerpt
```

Do not invent a page number when none is available.

## Output metadata

Use:

```text
schema_version = unstructured_source_transcription/v1
review_status = draft
reviewed_by = null
reviewed_at = null
```

Set `source_id`, `source_edition`, and `transcribed_from` from supplied metadata/source.

Before returning, internally check:
1. every record is actually supported by the supplied source;
2. every identifier/extension/MIME value is source-supported;
3. every record has a source locator;
4. source-native conclusions have not been rewritten into QNL criteria;
5. uncertain fields are flagged rather than guessed;
6. review status remains draft;
7. the result is one JSON object matching the supplied schema.
