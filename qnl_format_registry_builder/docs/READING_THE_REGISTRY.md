# Reading the registry

This guide is for preservation officers and registry users who need to interpret the outputs of a registry run.

The pipeline produces evidence-rich records. It does not make final institutional preservation policy on its own. External sources, institutional overlays, method profiles, and change events are kept separate so a reviewer can see why a format was flagged and decide what to do.

## Start with these files or collections

For a file-export run, start with:

| Output | Use it for |
| --- | --- |
| `registry.csv` | Spreadsheet review, filtering, sorting, and institutional decision capture. |
| `registry.json` / `registry.jsonl` | Full canonical records with identifiers, source evidence, overlays, hazard, readiness, trend, and provenance. |
| `run_report.json` | Summary counts, source status, validation warnings, and sample changes. |
| `coverage_report.md` | Human-readable summary of coverage and validation issues. |
| `raw_records.jsonl` | Source-level evidence records used for reconciliation. |
| `source_snapshots.json` | Source files/URIs acquired for the run, with hashes and cache metadata. |

For a MongoDB-backed run, start with:

| Collection | Use it for |
| --- | --- |
| `canonical_formats` | Current registry records. Query with `{current: {$ne: false}}`. |
| `assessment_changes` | Review queue generated by change detection. |
| `hazard_assessments` | Per-run hazard snapshots. |
| `institution_policy_overlays` | Local institutional decisions and terminology. |
| `format_identifiers` | Fast lookup by PUID, NARA ID, LOC ID, extension, MIME type, or another identifier namespace. |
| `source_records` | Source evidence and provenance. |

## The current registry view

A canonical format record is current when:

```javascript
{current: {$ne: false}}
```

A non-current record is retained for history. It means a canonical record was present in an earlier current view and no longer appears in the latest computed view.

Do not delete non-current records just because they are not current. They preserve change history.

## Identity and matching fields

| Field | Meaning |
| --- | --- |
| `canonical_id` | Stable local canonical ID used by the registry. It may be based on a verified strong identifier such as a PUID, or on a fallback when no strong identifier exists. |
| `preferred_name` | Reconciled display name chosen from source evidence. |
| `category` | Reconciled format family/category when available. |
| `identifiers` | Identifier values grouped by namespace, for example `puid`, `nara`, `loc`, `extension`, `mime`. |
| `identifier_claims` | Source-specific identifier claims, with `source`, `verified`, and `source_record_id`. Use this for provenance. |
| `source_records` | Evidence summaries from the sources that contributed to this canonical record. |

Important rule: only configured strong identifiers from authoritative or verified sources are used as strong reconciliation keys. A PUID copied from a spreadsheet is useful evidence, but it is not the same as a PUID verified by PRONOM.

Read [`IDENTIFIER_RECONCILIATION.md`](IDENTIFIER_RECONCILIATION.md) before changing adapter identifier behavior.

## Hazard and risk fields

| Field | Meaning |
| --- | --- |
| `hazard_assessment.band` | Current normalized hazard band, for example `Low`, `Moderate`, `High`, or an operational state such as `no_estimator_available`. |
| `hazard_assessment.basis` | Why the band was assigned. Examples: external-only evidence, corroborated evidence, institutional override, or no estimator. |
| `hazard_assessment.rating` | Normalized numeric rating where available. Do not assume the source-native direction. |
| `hazard_assessment.external_band` | External source hazard band when available. |
| `hazard_assessment.institution_band` | Institutional hazard/risk band when available. |
| `hazard_assessment.review_required` | Human review is needed. This is not the same as divergence. |
| `hazard_assessment.external_rating_native` | Source-native numeric rating, preserved exactly because movement inside a band can matter. |
| `hazard_assessment.external_rating_native_scale` | Name of the source-native scale. |
| `hazard_assessment.external_rating_native_direction` | Direction of the native scale, for example `higher_is_safer` or `lower_is_safer`. |
| `hazard_assessment.external_native_gap_to_institution_band` | Gap between source-native external evidence and institutional position when the system understands the source scale. |

## Terms that are easy to misread

### `institution_override`

This does not mean a person manually overrode a decision inside this system.

It means the institutional estimator and the external estimator disagree, and the current institutional position is being preserved as the active institutional view while review is required.

### `review_required`

This means a human should look at the record. It can happen for different reasons, including missing estimators, divergence, or other uncertainty.

It does not always mean external-vs-institutional divergence.

### `divergence_opened`

This is a change event. It should only mean two estimators are present and now disagree, or an explicit institutional override condition was introduced.

It should not fire simply because a record has `review_required: true`.

### `no_estimator_available`

This means the registry has no usable hazard estimator for the current canonical record. It is an honest state, not a pipeline failure by itself.

Typical action: identify a source, add institutional assessment, or mark the record for manual review.

### `external_rating_native`

This is not always intuitive. For NARA, a value such as `25` may be safer than `-30` because the source-native scale direction is preserved separately.

Always read it together with:

```text
external_rating_native_scale
external_rating_native_direction
```

### `Partially Covered`

This means a preservation pathway or method profile exists but has not been fully tested or confirmed for the institution's actual operational context.

It does not mean half of the files are complete.

### `Insufficient Evidence`

This is a deliberate honest default for trend or other evidence axes when no reliable connector or evidence exists yet.

It is better than inventing a trend.

## Institutional policy overlay fields

Institutional overlays capture how a specific institution interprets the evidence and records its local decision.

For QNL, common fields include:

| Field | Meaning |
| --- | --- |
| `institution_id` | Institution profile, for example `qnl`. |
| `institution_name` | Institution display name. |
| `institution_format_id` | Local format ID used by the institution. |
| `local_risk_level` / `risk_level` | Local risk language from the institution. |
| `preservation_action` | Current institutional action, for example preserve, monitor, convert, normalize, review, or retire, depending on local vocabulary. |
| `proposed_preservation_plan` | Proposed plan or handling pathway. |
| `preferred_tools` | Preferred tools for identification, validation, rendering, normalization, or conversion. |
| `conversion_process` | Local conversion or processing instruction. |
| `raw` | Original source row or useful subset for audit/debugging. |

Another institution may use different terms. The model should preserve their terminology through configuration rather than forcing QNL labels onto everyone.

## Change event fields

`assessment_changes` records differences between the previous current registry view and the newly computed view.

| Change type | Meaning | Typical review |
| --- | --- | --- |
| `record_added` | A canonical format appeared in the current view. | Decide whether institutional policy or readiness assessment is needed. |
| `record_removed` | A canonical format disappeared from the current view. | Confirm whether an upstream source intentionally removed it or config changed. |
| `preferred_name_changed` | The reconciled display name changed. | Check labels, aliases, and local documentation. |
| `category_changed` | The reconciled category changed. | Check method profiles and policy grouping. |
| `identifiers_changed` | Identifier values changed. | Review before using them for automated matching. |
| `hazard_band_changed` | Normalized hazard band changed. | Review institutional policy and action plan. |
| `hazard_basis_changed` | The basis for the hazard assessment changed. | Confirm source mix and review state. |
| `external_rating_native_changed` | Source-native numeric rating changed. | Review even when the normalized band stayed the same. |
| `divergence_opened` | External and institutional estimators now disagree. | Decide whether to keep the institutional position or update policy. |
| `divergence_resolved` | A previous divergence no longer exists. | Confirm closure of any related review action. |
| `source_coverage_changed` | Bulk changes were collapsed to a source-level event. | Validate source/configuration before reviewing every format. |

## Spreadsheet review workflow

A common institutional workflow is:

1. Run the registry.
2. Filter `registry.csv` or MongoDB records by hazard band, review flag, missing identifiers, no estimator, or source coverage.
3. Export the selected records to a review spreadsheet.
4. Let the institution analyse and record decisions using its own terminology.
5. Import the completed spreadsheet later as an updated institutional policy overlay.
6. Generate preservation actions from changed decisions or unresolved review states.

This keeps the evidence model separate from the institution's decision-making process.

## Interface review workflow

A later web interface can use the same records without changing the model.

A reviewer should see:

- format identity and identifiers;
- external evidence;
- institutional overlay fields;
- hazard assessment and review state;
- change history;
- suggested follow-up action;
- decision fields such as preserve, monitor, convert, normalize, review, defer, or retire.

The interface should store institutional decisions as overlay/action records, not rewrite source evidence.

## AI-assisted review workflow

Risk analysis may be manual or AI-assisted.

AI may help by:

- summarizing source evidence;
- explaining why a format is flagged;
- comparing external and institutional positions;
- highlighting missing identifiers or no-estimator states;
- drafting possible actions for a human reviewer.

AI should not silently approve institutional preservation policy. The final decision should be recorded as a human/institutional decision with provenance.

## Worked example 1: NARA-only PDF-style record

A NARA-only run may produce a canonical record with external hazard evidence but no institutional overlay.

What to read:

| Field | Interpretation |
| --- | --- |
| `source_records` | Shows NARA as the contributing source. |
| `identifiers.nara` | NARA source identifier claim. |
| `hazard_assessment.band` | External hazard band normalized from NARA. |
| `hazard_assessment.external_rating_native` | NARA native rating. Read with native direction. |
| `institution_policy_overlays` | Empty, because QNL has not added its local policy. |

Operational conclusion:

```text
The registry has external evidence. QNL still needs to decide whether this format is supported, monitored, converted, or otherwise handled locally.
```

## Worked example 2: External-vs-institutional divergence

A later run includes an institutional workbook. The same canonical format now has both external evidence and a QNL overlay.

Possible state:

```text
external_band: High
institution_band: Moderate
basis: institution_override
review_required: true
```

Interpretation:

```text
The external source and institutional position disagree. The system preserves the institutional position as the local decision layer but flags it for review. The reviewer decides whether QNL should keep the current position, change the local risk level, change the preservation action, or record a justification.
```

Do not average the two bands. Divergence is useful because it shows that a local decision needs attention.

## Worked example 3: No estimator after source withdrawal

A source refresh may remove the only external hazard estimator for a format while another source still contributes identity evidence such as a PUID.

Possible state:

```text
hazard_assessment.band: no_estimator_available
hazard_assessment.review_required: true
source_records: PRONOM only
```

Interpretation:

```text
The registry still knows the format identity, but no current hazard estimator is available. This requires review, but it is not external-vs-institutional divergence because there are not two disagreeing estimators.
```

Typical action: add institutional assessment, wait for an updated external source, or mark the format for manual analysis.
